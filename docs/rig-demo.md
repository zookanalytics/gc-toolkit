# Rig-demo mol

`mol-rig-demo` captures one narrated, captioned video demo of a rig's app and
either delivers it to a PR or reports where the clip landed. It is the reusable
capture capability: parameterized by rig and scenario, runnable against any rig.

The capture runs over the SprintShow engine (`skills/demo-capture`), engine-driven
— the engine drives Playwright headlessly, so the mol needs no browser MCP and
runs in an ordinary pool session. The mechanical core is
`assets/scripts/rig-demo-capture.sh`; the formula wraps it with scenario
resolution and delivery.

## Scope

**Mandate.** How to produce a demo clip of a rig's app through `mol-rig-demo`:
the pour, the inputs that name the rig, the scenario, and the app target, and
how the clip is delivered.

**Boundaries.** It does not cover the capture engine's internals or the
demo-script dialect (`skills/demo-capture`, `skills/gc-demo-script`), delivery
mechanics (`assets/scripts/demo-deliver.sh`), the toolchain and TTS-key
provisioning (`doctor/check-demo-toolchain`, specs/tk-vd66j1.1), or how PR review
decides a change needs a visual and pours this mol (specs/tk-vd66j1.5,
tk-vd66j1.6–.9).

## Pour it

```bash
gc sling <rig>/<pool> <demo-request-bead> --on mol-rig-demo \
  --var rig_name=<rig> \
  --var demo_script=<path.md> \
  --var serve_dir=<dir> \
  --var deliver_subject=<bead>
```

The bead the mol is poured on is a demo request: the mol fulfills it, records
where the clip went, and closes it.

## Inputs

| Var | Required | What it names |
|---|---|---|
| `rig_name` | yes | The rig whose app is demoed. Resolves to a checkout path, and is the root a relative `serve_dir` resolves against. |
| `demo_script` | one of | Path to a ready `demo:capture`-format script. |
| `source_bead` | one of | A bead whose work becomes the script, generated by following `skills/gc-demo-script/SKILL.md`. Use this or `demo_script`. |
| `serve_dir` | one of | Static directory the engine serves. Absolute, or relative to the `rig_name` checkout. |
| `serve_cmd` | one of | Dev-server command the engine spawns, waits for, and tears down. |
| `base_url` | one of | URL of a server already running. One of `serve_dir` / `serve_cmd` / `base_url`. |
| `serve_port` | no | Port for `serve_dir` / `serve_cmd` (default 5173). |
| `capture_mode` | no | `walkthrough` (default) or `proof`. |
| `narrate` | no | `false` forces a silent, captioned clip. A missing `OPENAI_API_KEY` is always silent. |
| `deliver_subject` | no | A bead whose PR receives the clip. |
| `deliver_pr` | no | A PR number or URL to receive the clip. Omit both to just report the path. |

### The app target is the one rig-specific input

`serve_dir` / `serve_cmd` / `base_url` is how the rig's app is reached, and it is
the one fact the mol cannot derive — `gc rig list` names a rig's path, not its
app. It is passed per pour. A stored per-rig default is tracked separately
(tk-8o3fck); until it lands, name the target on every pour.

### The scenario

The scenario is a `demo:capture`-format script. Pass one you have (`demo_script`),
or name a bead (`source_bead`) and the mol writes one by following the
`gc-demo-script` skill. A script is markdown that both reads as a walkthrough and
carries machine-checked assertions, so the clip shows verified behavior.

## The clip is an artifact, not a commit

The clip is written outside the repo tree and delivered to its PR as an inline,
uncommitted attachment (`demo-deliver.sh`) — the only way a video renders as a
player rather than a link. It is never committed: no `.gitattributes` LFS filter
covers an MP4. With neither `deliver_subject` nor `deliver_pr` set, the mol
records the clip's path on the request bead instead of delivering.

## Toolchain

The capture needs Node ≥ 22.18, a Chromium build, and ffmpeg; narration also
needs `OPENAI_API_KEY`. `doctor/check-demo-toolchain` reports which resolve. A
missing key degrades to a silent, captioned clip; it never fails the capture.

## Driving the script directly

`rig-demo-capture.sh` is usable without the mol — by the video review modality
(tk-vd66j1.9) or an operator — when the scenario script already exists:

```bash
assets/scripts/rig-demo-capture.sh --script <demo.md> --output <out.mp4> \
  ( --serve-dir <dir> | --serve "<cmd>" | --base-url <url> ) [--mode proof] [--no-narrate]
```

It resolves the engine, lints, captures, and fails closed if no MP4 is produced.
