Formula: mol-rig-demo
Description: mol-rig-demo — capture one narrated video demo of a rig's app, parameterized by
rig and scenario, and deliver it to a PR or report its path. The reusable
rig-demo mol of epic tk-vd66j1: the video review modality (tk-vd66j1.9) pours it
to produce a clip for a PR under review, and an operator pours it for any rig
from a shell.

  gc sling <rig>/<pool> <demo-request-bead> --on mol-rig-demo \
    --var rig_name=<rig> \
    --var demo_script=<path>            # or: --var source_bead=<bead>
    --var serve_dir=<dir>               # or: --var serve_cmd="<cmd>" / --var base_url=<url>
    --var deliver_subject=<bead>        # optional; or --var deliver_pr=<n>; omit to just report

The capture is engine-driven over @zookanalytics/sprintshow
(skills/demo-capture/SKILL.md): the engine drives Playwright headlessly, the
only path a pool session has, since it carries no browser MCP. The mechanical
half — engine resolution, lint, capture, liveness check — lives in
assets/scripts/rig-demo-capture.sh so this formula, tk-vd66j1.9, and a shell all
drive it the same way. Delivery is assets/scripts/demo-deliver.sh (tk-vd66j1.4),
which attaches the clip to the PR inline and uncommitted.

Two inputs name the scenario, and the mol needs exactly one: demo_script is a
ready demo:capture-format script; source_bead is a bead whose work the mol turns
into a script by following skills/gc-demo-script/SKILL.md. One input names how
the rig's app is reached — serve_dir, serve_cmd, or base_url — the one
rig-specific fact, threaded as a pour var because no rig-to-app map exists
(docs/rig-demo.md). A per-rig default store is tracked separately; this mol
reads the target from the pour.

The clip is an artifact, never a committed file: it is written outside the repo
tree and delivered to the PR, because a user-attachments URL is the only
inline-playable path and no .gitattributes LFS filter covers an MP4.

Contract: single continuation group, run inline in one session. Derive the
demo-request bead from the input convoy's single member; produce the script;
capture; deliver or report; close the request bead and the step chain forward;
drain. On any blocker, escalate.sh files one visit and molecule-hold.sh holds
the molecule before the drain, so a declined demo is never a silent strand.
NEVER commit the MP4, NEVER close or route a delivered PR's anchor.


Required vars:
  {{rig_name}}: Rig whose app is demoed. Resolved to a checkout path via `gc rig list`; also the default root for a relative serve_dir.

Optional vars:
  {{base_url}}: URL of a server already running, driven as-is. One of serve_dir / serve_cmd / base_url. (default=)
  {{capture_mode}}: walkthrough (default, one continuous recorded take) or proof (one checked screenshot per step). (default=walkthrough)
  {{deliver_pr}}: PR number or URL to deliver the clip to, when no deliver_subject names one. Optional. (default=)
  {{deliver_subject}}: A bead whose pr_number/pr_url names the PR to deliver the clip to. Optional; with deliver_pr unset too, the mol reports the artifact path instead of delivering. (default=)
  {{demo_script}}: Path to a ready demo:capture-format markdown script. Use this OR source_bead. Absolute, or relative to the capture session's cwd. (default=)
  {{narrate}}: Narrate the clip when OPENAI_API_KEY is set. 'false' forces a silent, captioned clip. A missing key is always silent, never a failure. (default=true)
  {{serve_cmd}}: Dev-server command the engine spawns, waits for, and tears down (e.g. 'npm run dev'). One of serve_dir / serve_cmd / base_url. (default=)
  {{serve_dir}}: Static directory the engine serves with its built-in file server. Absolute, or relative to the rig_name checkout. One of serve_dir / serve_cmd / base_url. (default=)
  {{serve_port}}: Port for serve_dir / serve_cmd. (default=5173)
  {{source_bead}}: A bead whose work becomes the script, generated by following skills/gc-demo-script/SKILL.md. Use this OR demo_script. (default=)

Steps (4):
  ├── mol-rig-demo.prepare-script: Resolve or generate the demo:capture script
  ├── mol-rig-demo.capture: Capture the narrated MP4 against the rig's app [needs: mol-rig-demo.prepare-script]
  ├── mol-rig-demo.deliver-and-finalize: Deliver the clip or report it, then close the request and drain [needs: mol-rig-demo.capture]
  └── mol-rig-demo.workflow-finalize: Finalize workflow [needs: mol-rig-demo.deliver-and-finalize]
